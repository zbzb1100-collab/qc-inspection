# 驗屋報告判讀規則

排程每次轉檔都照這份規則做，讓不同報告、不同時間轉出來的結果一致。
要改判讀方式就改這份檔（例如工務所確認了某個對應），不要只在對話裡講。

## 流程

1. `python3 tools/report_worker.py claim W`：領一份待轉檔的報告。印出 `NO_JOB` 就結束這次排程。
   W 裡會有：
   - `report.pdf`：要讀的報告。
   - `job.json`：上傳者選的棟／樓／戶／檢查類型，在 `_label` 欄；`note` 是上傳者給的提醒。
   - `lists.json`：系統目前的清單。
2. 把 PDF 每頁轉成圖片來看（例如 `pdftoppm -r 110 -png`）。不要只靠抽文字，很多報告的文字是圖片，抽出來會亂。
3. 照下面的規則寫 `W/rows.json`，照片裁好放在 `W/photos/`。
4. `python3 tools/report_worker.py check W`：把「錯誤」都修掉。「提醒」可以留著，那些列會在系統預覽時變成黃色待補選。
5. `python3 tools/report_worker.py submit W`：上傳照片、寫回結果。
6. 讀不了的話（不是驗屋報告、檔案壞掉、整份跟這戶無關），用 `python3 tools/report_worker.py fail W 原因` 標記失敗。原因要寫給工地同事看得懂，例如「這份是 E1-02F 的報告，跟上傳時選的 E1-17F 不同」。
7. 一次排程最多處理 3 份；還有剩就留給下一次。

## rows.json 格式

```json
{"rows": [{"棟別":"E棟","樓層":"17F","戶別":"E1","檢查類型":"驗交屋","空間":"客餐廳","工項":"金屬門工程",
           "缺失內容":"門扇與門框密合度不良","修繕方式":"","修繕廠商":"","責任廠商":"",
           "缺失說明":"大門上方磁簧變形","照片":"L-1.jpg","報告編號":"L-1","對應備註":""}],
 "skip": [["補充-2","檢驗當日停車場車位未完成","屬公設，不是此戶缺失"]],
 "message": "給上傳者的一句提醒（選填），例：第 2、5 項空間不確定"}
```

## 每一欄怎麼填

- **棟別、樓層、戶別、檢查類型**：一律照 `job.json` 的 `_label` 填。
  報告寫的戶別跟上傳時選的不同，就用 fail 標記失敗，不要自己改。
- **一項缺失一列**：
  - 報告一個編號裡寫了兩件不同的事（例如「門框清潔」和「磁簧變形」），拆成兩列，報告編號相同。
  - 同一件事出現在兩個地方，也拆成兩列。
- **空間**：
  - 只能用清單裡的名稱。`lists.json` 的 `unit_spaces` 有值時，優先從裡面選。
  - 報告的說法對到清單的說法，看下面的「對應表」。
  - 整戶性的項目填「全室」。
- **工項、缺失內容**：
  - 依意思對到清單，缺失內容一定要在該工項底下。
  - 對到最接近的但不完全吻合時，照填，並在「對應備註」寫原因，例如「清單無『開縫』，暫選不平整」。
  - 對不到時用該工項的「其他缺失」，細節看下面「缺失 → 工項／缺失內容」。
- **修繕方式、修繕廠商、責任廠商**：留空。系統會依工項自動帶預設廠商，修繕方式由工務所自己選。
- **缺失說明**：
  - 照報告原文完整抄寫，包括位置、數量（例如「*1處」）和建議做法。
  - 不要改寫，也不要摘要。
- **照片**：
  - 從報告裁出該項的照片，存成 JPEG，用報告編號命名：`L-1.jpg`。
  - 一項有多張時，命名為 `L-1.jpg`、`L-1-2.jpg`，在「照片」欄用「、」隔開。
  - 一張照片可以給好幾列共用。
  - 只裁照片本身，不要連頁首、表格框或文字一起裁進去。
  - 沒有照片就留空。
- **報告編號**：
  - 照報告上的編號抄。
  - 報告沒有編號時，用「頁碼-序號」，例如「P5-2」。
  - 報告最後的補充或總評項目，用「補充-1」「補充-2」。
- **對應備註**：只寫「為什麼這樣對」或「需要人確認什麼」。有把握的列留空。
  - 滲水、漏水、結構裂縫這類重要項目，開頭加「重要：」。
- **skip（不匯入）**：以下這些不寫進 rows，寫進 skip，格式是 `[編號, 內容, 原因]`：
  - 不屬於這一戶的項目，例如公設、停車場、其他戶。
  - 報告寫明已改善、合格或無缺失的項目。
  - 純說明文字，例如檢驗方法、免責聲明、儀器資料。

## 缺失 → 工項／缺失內容

2026-10-19 依 105 份實際報告（20 家驗屋公司）定版。工項名稱沒有數字，每個工項最後都有「其他缺失」。

### 歸類原則

- **先找最貼切的缺失內容**，照下表的「報告常見寫法」判斷意思，不要求字面相同。
- **一句寫了好幾種缺失**（例如「髒污、刮傷、收邊不良」），每種拆一列，報告編號相同。
- **門窗框與牆面交界的收邊、填縫不實**，不論金屬門、木門或鋁窗，都歸「油漆工程 → 油漆收邊不良（與門窗框邊、牆腳交界）」。
- **欄杆、格柵、鐵件**都歸「金屬工程」。
- **踢腳板**歸「木地板工程」（沒有踢腳板工程）。
- **工程未完成、未完工**：當缺失，依部位歸到該工項：
  - 馬桶、熱水器、蓮蓬頭沒裝 → 衛浴設備 → 設備未安裝（馬桶、熱水器、蓮蓬頭等）
  - 其他部位 → 該工項的「其他缺失」，例如水槽或爐具歸廚具工程，門鈴歸監控系統，牆面歸油漆工程。
- **待確認、請業主確認**（例如「熱水器洩壓軟管待確認」）→ 該工項的「其他缺失」。
- **設計不良、設計建議** → 該工項的「其他缺失」，缺失說明開頭加「（非缺失，設計建議）」。
- **無法測試**：
  - 設備沒做好所以不能測（例如「熱水器未完工未測試」）→ 當缺失，照「工程未完成」歸。
  - 缺遙控器或控制面板 → 衛浴設備 → 配件缺件（蓋板、止水塞、把手等）。
  - 不便攀爬、待交屋或建商測試、保全或停車場未測 → 不是缺失，寫進 skip。
- **有工項但對不到缺失內容** → 該工項的「其他缺失」，對應備註寫「清單無…，暫選其他缺失」。
- **連工項都判斷不了** → 工項「其他」→「其他缺失」，對應備註寫「對不到：…，請手動選」。
