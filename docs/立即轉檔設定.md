# 優先轉檔／立即轉檔設定

管理員在「報告」分頁勾選待轉檔的報告，按「優先轉檔」，下一次排程會先轉這幾份。
一般使用者看不到這個按鈕，照樣上傳後排隊。

**現在只要做第 1 步**：做完就能用「優先轉檔」。
2026-10-19 檢查過，claude.ai 的排程頁目前只有「排程」一種觸發方式，沒有 API，所以第 2、3 步（按了馬上跑）暫時做不到。
等排程頁的「觸發方式」出現 API 選項，再做第 2、3 步，網站不用改，按鈕就會變成按了馬上跑。
在那之前要馬上轉，請在專案裡跟 Claude 說「立即轉檔」，Claude 可以直接叫排程跑一次。

第 2、3 步的做法：過程中會拿到一把「觸發鑰匙」，**只貼在 Supabase 的 Secrets，不要貼到聊天、Excel 或網站程式裡**。

## 1. 執行 SQL

Supabase 後台 → SQL Editor → 貼上 `11_立即轉檔.sql` 全部內容 → Run。

## 2. 拿排程的觸發網址和鑰匙

1. 打開 https://claude.ai/code/routines ，點「驗屋報告轉檔」。
2. 名稱旁的選單 → Edit。
3. 「Select a trigger」底下按 Add another trigger → 選 API。
4. 畫面會出現一個網址，先複製起來（這是觸發網址）。
5. 按 Generate token，複製鑰匙。**鑰匙只顯示這一次**，關掉就看不到了（弄丟可以再按 Regenerate）。
6. 存檔。原本的「每小時」排程不要刪，兩種觸發會並存。

## 3. 在 Supabase 部署 fire-convert

1. Supabase 後台左邊 → Edge Functions → Deploy a new function → Via Editor。
2. 函式名稱填 `fire-convert`。
3. 把 `fire-convert.ts`（repo 裡是 supabase/functions/fire-convert/index.ts）全部內容貼上，取代預設的範例程式 → Deploy function。
4. Edge Functions → Secrets（或 Project Settings → Edge Functions → Secrets），新增兩筆：
   - `ROUTINE_FIRE_URL`：第 2 步複製的網址
   - `ROUTINE_TOKEN`：第 2 步複製的鑰匙
5. 回到系統，用管理員帳號到「報告」分頁，勾一份待轉檔的報告按「立即轉檔」試試看。幾分鐘後按「重新整理」，應該會變成「已轉好」。

## 如果按了顯示錯誤

| 畫面訊息 | 原因 |
|---|---|
| 要先到 Supabase 執行 11_立即轉檔.sql | 第 1 步還沒做 |
| （Supabase 還沒部署 fire-convert） | 第 3 步還沒做，或名稱不是 fire-convert |
| 還沒設定 ROUTINE_FIRE_URL / ROUTINE_TOKEN | 第 3 步的 Secrets 少了或名字打錯 |
| 叫不動排程：401… | 鑰匙錯了或被重新產生過，回第 2 步 Regenerate，再更新 Secrets |
| 叫不動排程：429… | 這個排程一小時內被叫太多次（上限 30 次），等一下再試 |
| 只有管理員可以要求立即轉檔 | 這個帳號不是管理員 |
| 其他 401 Invalid JWT | 到 fire-convert 的設定把「Verify JWT」關掉再試（程式本身會檢查是不是管理員） |

不管哪一種錯誤，勾的報告都已經排到最前面，最晚下一個整點也會轉。

## 用量

每按一次立即轉檔，排程就多跑一次，跟整點排程一樣算在 Claude 方案的用量裡。一次最多處理 3 份；勾超過 3 份會自動多叫幾次（最多 4 次）。
